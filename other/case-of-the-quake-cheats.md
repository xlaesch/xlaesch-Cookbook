
open-source software such as linux and apache is fundamentally more secure than its closed-source competitors. 
- encryption can only be considered safe after it has been repeatedly attacked by experts with full knowledge of the algorithms it uses

asking an open-source client to verify its own correctness won't work because a cracker could always write a client that would simulate the right kinds of responses then cheat.

a bank should not depend on a customer's client software to tell the bank what the customer balance is.

a truly secure system doesn't trade away security to get performance. In quake, to hold down the number of updates the Quake world has to pass to the client. the servers gives the client information about object and opponents the player can't see: this violates the minimum disclosure security design principle. 

A security conscious designer must assume that the clinet knows the information immediately upon its receipt, regardless of its form (encrypted, hashed, etc).

open source keep designer honest by depriving them of the crutch of obscurity and forcing them to use methods that are provably secure not only against known attacks but against all possible attacks. 

- never trust a client to be honest
- you can't have real security if you trade it away to get performance
- real  security comes not from obscurity but from minimum discolusre and threat monitoring
